# P5 设计冻结：受控批量、状态与可读导出

## 目标与边界

P5 在独立候选环境提供有限批量的既有受控工况计算、状态可见性与同源汇总导出。它不新增热力学模型、不改变 P1–P4 设备契约、不接收客户资料、不生成企业 Word 或报价，也不部署生产。

## 执行模型

服务端维持一个单消费者 FIFO 队列。每个批次最多 `10` 个工况、每项请求体沿用既有严格输入校验、逐项串行调用现有 `server.calculate`。item 执行终态仅为 `succeeded` 或 `failed`；批次为 `queued`、`running`、`completed`、`completed_with_failures`。页面另有非终态等待事件 `wait_timed_out_at`：它只表示本次轮询/HTTP 等待已超过明确的等待预算，绝不改变 item 终态或把迟到结果回写成新的成功。队列在真实求解返回并完成事务提交后才领取下一项。

运行中的 DWSIM 求解不可取消：页面不提供“取消”语义，也不得终止共享引擎或伪造已取消状态。等待预算、HTTP 长轮询预算和单次 DWSIM 计算预算分别配置并展示；前两者只提示“仍在运行，请刷新”，单次计算预算由既有引擎调用超时转换为 `failed` 并记录错误摘要。测试必须分别覆盖三种预算。

SQLite 是唯一领取协调者：领取使用短事务将最早 `queued` item 原子更新为 `running`，写入唯一 worker token 与租约截止时间；所有 worker 均只能领取成功后执行，故不会并发调用 DWSIM。租约仅在执行期间续期；重启恢复将过期 `running` item 置回 `queued` 并递增 attempt，超过一次恢复尝试则置为 `failed`，不在未知结果下重复执行。请求 idempotency key 绑定 owner、批次与规范化输入；已完成 item 不可变，重复提交仅返回原 item。

批次汇总规则：任一 item `running` 则批次 `running`；存在 `queued` 且无运行项则 `queued`；全部成功为 `completed`；存在失败且无未完成项为 `completed_with_failures`。保留最近 90 天或每 owner 100 个批次（先到者清理，仅清理已完成批次）；清理前不修改项目、run 或导出记录。

## 数据与导出

批次记录写入候选独立持久化目录；每项保存原始 JSON，并生成同源 CSV 与打印版 HTML。所有批次/下载按既有认证 owner 隔离；写操作同时要求 Basic Auth、同源 Origin 与 nonce。ID 由服务端生成并采用固定正则，导出路径由服务端映射，下载再次校验 owner；不接受客户端文件路径、列名或 HTML。可读导出必须包含输入和值的单位、物性包、应用/引擎版本、提交时间、假设、最终状态、比较指标和错误摘要；图表只使用已成功项的同一记录数据。CSV 对公式起始字符转义，HTML 对所有文本进行上下文转义且使用固定模板，禁止原始 JSON 作为 HTML 插入。

## 验收

候选必须验证：忙碌/等待/超时文字；`1/2/10` 项批量与第 `11` 项拒绝；成功、输入失败、引擎失败、超时的逐项记录；原始 JSON 与 CSV/打印/图表同源；P1–P4 回归；DB/批次恢复与回退；Chrome `1440/390` 无横向溢出且错误提示可见。仅在总控独立复核 P5 候选包后才可讨论生产发布。
