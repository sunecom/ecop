# P5 设计冻结：受控批量、状态与可读导出

## 目标与边界

P5 在独立候选环境提供有限批量的既有受控工况计算、状态可见性与同源汇总导出。它不新增热力学模型、不改变 P1–P4 设备契约、不接收客户资料、不生成企业 Word 或报价，也不部署生产。

## 执行模型

服务端维持一个单消费者 FIFO 队列。每个批次最多 `10` 个工况、每项请求体沿用既有严格输入校验、逐项串行调用现有 `server.calculate`。状态仅为 `queued`、`running`、`succeeded`、`failed`、`timed_out`；显示队列位置、开始/结束时间、明确的服务端超时上限与错误摘要。

运行中的 DWSIM 求解不可取消：页面不提供“取消”语义，也不得终止共享引擎或伪造已取消状态。超时仅表示调用等待上限已到；当前求解完成后队列才会继续，记录最终真实状态。请求失败、超时或进程恢复后均保留逐项审计状态。

## 数据与导出

批次记录写入候选独立持久化目录；每项保存原始 JSON，并生成同源 CSV 与打印版 HTML。可读导出必须包含输入和值的单位、物性包、应用/引擎版本、提交时间、假设、最终状态、比较指标和错误摘要；图表只使用已成功项的同一记录数据。CSV 采用受控字段和公式注入转义，不接收自由列名或路径。

## 验收

候选必须验证：忙碌/等待/超时文字；`1/2/10` 项批量与第 `11` 项拒绝；成功、输入失败、引擎失败、超时的逐项记录；原始 JSON 与 CSV/打印/图表同源；P1–P4 回归；DB/批次恢复与回退；Chrome `1440/390` 无横向溢出且错误提示可见。仅在总控独立复核 P5 候选包后才可讨论生产发布。
